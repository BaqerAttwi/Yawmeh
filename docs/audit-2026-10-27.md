# Website audit — 27 October 2026

## Result

The reviewed application builds successfully. All 129 automated tests pass,
including authorization, ownership, password recovery, sessions, accounting,
planning, currency handling, reminder logic and speech proxy tests.
The final dependency audit reports zero known vulnerabilities.

This review covers the local source, automated HTTP tests and browser demo.
It does not establish that every possible button sequence or a deployed service
is defect-free. HTTP write tests use an in-memory database; no real user records
were modified. The live MySQL check was read-only.

## Fixed

1. Updated the dependency lockfile to patched body-parser 2.4.0,
   Nodemailer 10.2.1, Vite 6.4.5 and Zod 4.6.7. The initial audit reported four
   affected packages (three high severity, one moderate). Raised the declared
   minimum Nodemailer and Vite versions and migrated the Zod requirement.
2. Adapted subscription payment validation to Zod 4's object schema API.
   Subscription payment and currency integration tests pass after migration.
3. Changed the global API rate limiter to return a JSON error. Previously its
   text response made the browser report an unavailable server instead of the
   actual throttle reason. Added an HTTP regression assertion.
4. Made the browser audit accept Windows absolute Playwright module paths.
   Expanded its interactions and layout coverage to task subtasks,
   completion/reopening and expanded daily tools.

## Routes and security

Reviewed route declarations in the Express app and auth, recovery, planning,
daily, money, insights and speech modules, alongside client API calls.
Added a deny-access matrix for 33 method/path combinations: 66 HTTP checks
cover anonymous requests and signed-in accounts without required permissions.
Existing integration tests exercise permitted requests and cross-user denial.

Controls inspected include parameterized SQL, owner predicates, app permissions,
admin-only account management, scrypt passwords, hashed sessions and reset
tokens, cookie flags, origin checks, JSON/body limits, security headers,
transaction locking and upstream speech limits. API responses are uncached;
the service worker caches only the public offline page.

The UI uses component state to switch workspace pages, rather than URL routes.
Browser reload returns to the default workspace view. Unknown authenticated
API paths return JSON 404; paid `/api/chat` is intentionally disabled.

## Browser verification

Headless Edge completed 80 recorded layout checks at 320, 375, 768, 1024 and
1440px widths, with no page exceptions or unintended horizontal overflow.
Covered Overview, Dashboard, History, Weekly review, Calendar, Money and its
tabs, Tasks, Users & access, Settings, expanded daily tools and companion chat.
Scrollable tables/tab strips and clipped decorations are intentional.

At each width the audit created a demo task, switched its form into Arabic
and back, saved it, added and checked a subtask, completed and reopened the
parent, changed energy, captured an inbox note and asked the companion a
question. Browser artifacts are in ignored `test-results/`.

## Setup and remaining launch work

- MySQL is reachable and all required tables/columns are present.
- SMTP is not configured. Real reminder/reset email delivery remains untested.
- Paid provider keys are not configured. Speech tests use a stub provider;
  real paid speech is untested. The free local companion works in browser tests.
- Secure cookies are currently disabled for local HTTP. Production must set
  `NODE_ENV=production`, `COOKIE_SECURE=true`, and an explicit HTTPS
  `APP_ORIGIN`. Startup enforces these production requirements.
- Run one app instance initially. Behind a reverse proxy, the current IP
  limiter sees the proxy address unless trusted proxy handling is configured
  deliberately; otherwise different visitors share the 120/minute bucket.
  Multi-instance deployments also need a shared rate-limit store.
- Configure HTTPS, SMTP, a restricted database user, private MySQL networking,
  service restart supervision and off-server database backups before launch.
  Perform an actual backup restoration and a live sign-in/reset/reminder smoke
  test on the chosen host. Confirm email port availability with that provider.
