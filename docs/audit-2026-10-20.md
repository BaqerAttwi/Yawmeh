# Code, security and responsive review — 20 October 2026

## Scope

Reviewed authentication and recovery, account permissions, Express middleware,
database access and migrations, money and currency rules, planning and reminders,
client mutations, companion storage and voice lifecycle, and responsive styles.
Ran the existing automated suite, JavaScript syntax checks, dependency audit,
production build, read-only database diagnostics and browser checks.
This is a development review, not a penetration test or a guarantee of no defects.

## Fixes

- **Sign-in race:** Password verification happens asynchronously. Previously a
  password reset or administrator disabling an account could occur after the
  account lookup but before insertion of a new session. Session creation now
  locks the user row, rechecks the verified password hash and active status, and
  inserts the session within the same transaction. A changed account receives
  no session cookie. This uses an explicit lock rather than relying on the
  database's default isolation level.
- **Calculated dates:** Date arithmetic for repeats, renewals and rescheduled
  reminders now rejects results outside MySQL's 1000–9999 year range instead of
  generating truncated extended-year strings or unsupported reminder dates.
  Calendar forecasts stop at the upper boundary.
- **Phone layouts:** Form controls and grid columns can shrink to their
  containers. Small screens use single-column field pairs and summary cards.
  Currency forms no longer enforce a 210px minimum within narrower cards.
  Dashboard columns constrain their contents and quick actions wrap. Mobile
  form text uses 16px to reduce automatic zoom when focusing inputs.
- Added regression tests for date boundaries and session creation, plus a
  reusable browser audit in `tests/browser-audit.mjs`.

## Remaining verification and deployment work

- SMTP and AI providers are unconfigured here. Real delivery, recognition,
  speech playback and paid provider responses were not verified.
- The new session transaction has regression coverage using doubles; live
  database concurrency and end-to-end account/money workflows remain untested.
- Mobile checks emulate viewport sizes in Edge. Real iOS/Android keyboards,
  microphone permissions and installed PWA behavior need device testing.
- Secure cookies are currently disabled in local configuration. Existing
  production startup checks require secure cookies and an explicit HTTPS
  origin. HTTPS termination and proxy/IP rate-limit configuration still depend
  on the deployment environment.
- Durable financial-request idempotency, backup restoration drills, distributed
  rate limiting and multi-user load testing remain production hardening work.

Restart the Node server to load the authentication changes. No schema migration
is required for these fixes.
